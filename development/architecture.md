# Architecture

## Transport and clocks

`Transport::render` is independent of Qt and runs in one audio device callback at 48 kHz. Before each output sample, it checks markers at the current integer show position. Holds consume their markers and freeze show time before rendering that sample. Abrupt cuts (Stop All, holds and pauses of normal clips, seeks, show end, a clip's timeline end inside its source, cache misses) render a 120-frame (2.5 ms) linear tail from the frames the voice would have played; a separate tail slot means tails never disturb read-ahead and simply end if their block is not resident. Normal voices that become audible mid-source fade in over the same length; clips arriving at their own source start do not. Voices cache their envelope segment and pan gains. Normal clips become silent; async sources keep advancing and evaluate automation at the frozen show time. The audio device remains running.

An async clip beginning exactly at a hold starts on arrival. Loops wrap to the source-in point. One-shots become Finished at source end and do not retrigger because show time remains inside them. Play from Held sends resume MIDI once and advances show time; same-time holds are consumed together. Manual pause cannot consume a held cue.

Seek changes show time and rearms markers without sending MIDI. It preserves running/finished async state inside the clip's half-open interval and clears it outside. Dormant sources start at the sought source position during playback. Stop All clears voices without rewinding. Show end clears all voices; a final hold can wait for the operator to resume into the end.

## Thread boundaries

The armed Show is immutable and references prepared audio sources. UI edits validate a candidate before committing, pause the open stream (closing it only if it failed), then swap the snapshot and resume. Re-arming keeps the read-ahead of clips whose source, offset, and loop are unchanged and only prebuffers new or changed clips. SPSC queues carry commands and MIDI events; MIDI capacity is allocated while disarmed and scales to the project marker count. Published status uses lock-free atomics. The callback does no allocation, disk I/O, mutex locking, Qt work, or MIDI sending.

Voice state and active-clip storage are allocated while disarmed. Stable sorted indices schedule clip starts and markers; per-sample work visits active audio clips and the markers at the current boundary instead of scanning the entire show. Seeking rebuilds the active set and locates the marker cursor without allocating. Clip completion retires voices; held async voices continue under the same rules as resident sources.

Audio legs mix into one interleaved device buffer. Tracks map L/R legs to physical channels; −1 disconnects a leg. Pan is constant-power for mono and balance attenuation for stereo. A track with exactly one connected leg receives the source summed to mono at full level and ignores pan. An RtAudio error callback marks the stream failed, and the controller treats a running stream whose callback count stalls for 750 ms as stopped; both stop playback with the driver's reason. Overload clamps at the device boundary and latches an indicator; non-finite samples are silenced and latch it too. Tracks align sample-exactly because there is one callback/clock. Playback cost depends on simultaneous voices and device channels rather than total timeline length; practical polyphony still requires hardware rehearsal.

## Media and picture

QtConcurrent import/open jobs use FFmpeg to probe and decode audio incrementally into temporary 48 kHz interleaved stereo float PCM files. Decoding retains one conversion chunk and 10 ms waveform peaks rather than the whole PCM in RAM. Audio/video share the container timestamp origin; a sparse silence prefix or incremental start trimming preserves embedded-stream offsets. Any one-channel input decodes as centre mono. Mono/stereo audio is supported; larger channel layouts still require separate stems.

Each armed disk-backed clip owns four 8192-frame read-ahead slots. One transport disk worker fills them; release/acquire ownership prevents it from overwriting a callback-held slot. The initial offset (or sought position when arming) is prebuffered before the device opens, including loop lookahead. During playback the callback requests source blocks using an atomic cursor, reads published slots, and advances async cursors only after all required sources are ready. Seek, Stop All, and arming point every disk source at the frame it will play next, so clips that already played read ahead again before re-entry. A miss leaves the remaining device block silent and freezes show/source clocks for a retry; waits are visible in the editor. Transient read failures (a locked file or briefly missing drive) retry every 25 ms and are counted in the editor; they latch only after persisting for 2 s. A source whose size or content no longer matches latches at once. Latched errors are published to the controller, which stops playback; Play re-arms to retry, and changed sources require reopening the project.

Sources and cache lifetime are shared by project/undo/armed snapshots. The last owner deletes the temporary file. Cache creation/write failures report the underlying error, including disk exhaustion; partial imports remove their temporary files. Project JSON still references original media paths and remains version 1 compatible. Reopening reuses caches by content hash. A stamp index (path, size, modification time → hash) skips rehashing unchanged sources, and direct WAVs keep their block hashes and peaks in a sidecar. Startup and each new cache trim the cache directory to min(20 GiB, 25% of free space plus the cache) by least-recent use, never removing caches that this or another instance has open, and expire caches from other decoder revisions after 7 days unused. Generated demo/test sources can remain resident.

Video workers have bounded lookahead caches. They skip and count corrupt packets, failed decodes, and read errors; seeks fall back to the stream start. Only an unopenable file, a missing video stream, or more than 50 consecutive failures stop a reader, which then keeps returning its last frame. Looping clips preroll up to 13 frames of the loop start before the wrap. At most the active and closest upcoming video per layer are retained. Frames downscale to project bounds before caching. The GUI composites images/text in layer order using show-time transformations. Preview and physical output receive the same final QImage. If a requested frame is not ready, the previous composition remains and the wait counter increments; audio continues independently. Video errors are reported once per clip and never stop audio or cues.

Software picture composition, GUI presentation, refresh, and device/display latency are remaining performance risks. GPU composition and hardware decoding should follow profiling on the show PC; output is not genlocked.

## MIDI

A dedicated 1 ms polling worker sends RtMidi messages from an immutable snapshot. Seek/Stop All advance an epoch to invalidate stale queued events. The worker joins before reconfiguration. The bridge is a native MIDI port; no network protocol is assumed. Complete MIDI 1.0 messages, including bounded SysEx, are validated. The cue editor maps musical values to the existing byte representation: note names, named controllers, programs 1–128, and signed pitch bend centered at zero. Test sending joins the worker before sending directly, then restarts it; testing requires editability. An RtMidi error callback turns failed sends into a lost port instead of a printed warning. Once a second, the controller checks that the remembered destination is still listed: a vanished port is closed and reported, and a returning port reconnects by name during playback or holds. Resuming a hold or pause never blocks on MIDI or missing video; it warns and continues.

On Windows the app requests 1 ms timer resolution so these polling workers wake on time. Scheduling has OS/driver jitter and may precede audible buffer presentation. Measurement and compensation are future work.

## Projects

`.savshow` is versioned JSON with integer audio-frame timing and relative media paths. Missing or unreadable media loads as an offline asset that keeps its reference and clips; validation skips source checks for it, playback from Stopped is blocked until it is relinked (File → Relink missing media searches a folder by file name), and resuming a live show only warns. Parsing type-checks every field before any media loads; absent optional fields keep their version-1 defaults. Validation checks IDs, representable frame timing, routing, MIDI, envelope ordering, and picture overlaps. Dynamic project collections have no prototype count caps; picture overlap validation sorts by layer/time instead of comparing every pair. Frame fields must be exact nonnegative integers within the JSON double integer range; clip bounds use subtraction to avoid addition overflow. The timeline scales scroll coordinates when its pixel width exceeds the scrollbar integer range. QSaveFile replaces files atomically. Generated demo assets export on first save; other media stays external. Undo/redo retains 32 snapshots sharing media; a successful save rewrites their asset paths so undo never restores temporary package or unsaved generated sources. Editing/audio-MIDI connection changes/saving require no active playback or async voices; Show mode additionally locks seeks and Outputs access. In edit mode, Outputs remains accessible during playback/holds for inspection and program display controls. Connection controls show their locked state and offer Stop All to unlock; inspecting a live show avoids probing audio and MIDI drivers. On Play, while stopped with no active async voices, the controller prepares the remembered audio device (or the system default on first use) and the remembered MIDI destination when required. This preparation also works in Show mode. Missing remembered devices never fall back to other destinations. Device selection connects immediately; channel/buffer changes have a separate Apply action.

`.savpack` is an export/interchange container: a ZIP/Zip64 archive holding the existing version-1 `project.savshow` plus all media library sources under `media/`. libarchive streams source bytes in 1 MiB chunks into an atomic QSaveFile; imported sources are not transcoded or additionally compressed. Canonical source paths deduplicate repeated references, while UUID filenames avoid platform naming conflicts. Generated sources are staged as PNG/WAV. Export runs on a worker while a modal progress dialog keeps the GUI responsive and prevents edits; it leaves the project path, dirty state, and source references intact.

Package opening first reads every header and the manifest, then extracts. It accepts only the manifest plus stored (uncompressed) regular files named `media/<uuid>.<ext>` that the manifest references, and checks the declared media size against free temporary space. It rejects duplicate/case-colliding entries, links, encryption, traversal, missing/external references, and malformed/truncated/CRC-failing archives before loading sources. QFile callbacks handle native Unicode archive paths. A shared QTemporaryDir on Project keeps extracted sources alive across undo/redo snapshots; the last owner removes them. Open extractions hold a lock file, and startup removes unlocked extraction/export folders older than a day that crashed instances left behind. The UI opens packages as unsaved editable copies. Normal Save materializes extracted sources into a persistent sibling `.media` folder and re-arms video readers against the new paths; subsequent autosaves use the existing JSON sidecar mechanism. Packages omit temporary PCM caches, local device preferences, and fonts.

## Roadmap

1. Physical ASIO routing verification on Windows show hardware, including interface unplug/reconnect and full rehearsal runs.
2. Measure display and MIDI bridge latency, then add compensation.
3. Profile four-layer 1080p24 and long shows; measure disk-cache read-ahead and add GPU/hardware decoding.
4. Crash logging and signed/notarized installers.
5. NDI using the composed picture.

Smaller known follow-ups: async voices that start mid-source still start without a fade-in, and saving an opened package copies extracted media instead of trying a rename first.
